## Otázka 1: SQL dotaz pro založení nového záznamu

Jaký typ SQL dotazu se použije ve vaší aplikaci pro založení nového záznamu do datasetu?

### Odpověď:

Aplikace využívá **INSERT** dotaz. V kódu se tento dotaz neprovádí přímo, nýbrž přes SQLAlchemy ORM, která SQL dotazy generuje automaticky.

Ekvivalentní SQL dotaz by vypadal takto:

```sql
INSERT INTO bird (nazev, vedecky_nazev, rad, celed, delka_cm, rozpeti_cm, hmotnost_g, status_ohrozeni, typ_potravy, migrace, vyskyt_kontinent, snuska_ks)
VALUES ('Vlaštovka obecná', 'Hirundo rustica', 'Pěvci', 'Vlaštovkovití', 18, 33, 18, 'Málo dotčený', 'hmyzožravec', 1, 'Evropa', 5.0);
```

V aplikaci je to implementováno v [main.py](../main.py#L22-L56) v rámci funkce `add_bird()`:

```python
new_bird = Bird(
    nazev=nazev,
    vedecky_nazev=vedecky_nazev,
    rad=rad,
    celed=celed,
    delka_cm=delka_cm,
    rozpeti_cm=rozpeti_cm,
    hmotnost_g=hmotnost_g,
    status_ohrozeni=status_ohrozeni,
    typ_potravy=typ_potravy,
    migrace=migrace,
    vyskyt_kontinent=vyskyt_kontinent,
    snuska_ks=snuska_ks
)
db.session.add(new_bird)
db.session.commit()
```

SQLAlchemy automaticky generuje a spouští INSERT dotaz na základě objektu `Bird`.

## Otázka 2: Dekorátor pro mazání záznamů

Napište dekorátor, který používá funkce implementující obsluhu mazání záznamů z databáze.

### Odpověď:

**Aplikace v současné době nemá implementánu funkcionalitu pro mazání záznamů.**

Pokud bychom chtěli přidat mazání záznamů, vypadal by dekorátor takto:

```python
@app.route('/delete/<int:bird_id>', methods=['POST'])
def delete_bird(bird_id):
    bird = Bird.query.get(bird_id)
    if bird:
        db.session.delete(bird)
        db.session.commit()
        return redirect(url_for('index'))
    return redirect(url_for('index'))
```

**Vysvětlení:**
- `@app.route('/delete/<int:bird_id>', methods=['POST'])` - dekorátor, který mapuje cestu na tuto funkci
  - `<int:bird_id>` - parametr v URL, který se předá jako ID ptáka
  - `methods=['POST']` - pouze POST metoda z bezpečnostních důvodů
- `Bird.query.get(bird_id)` - načtení ptáka z databáze podle ID
- `db.session.delete(bird)` - označení záznamu k smazání
- `db.session.commit()` - potvrzení změny v databázi

Odpovídající SQL dotaz by byl:
```sql
DELETE FROM bird WHERE id = 1;
```

## Otázka 3: Nahrání počátečních dat do databáze

Popište, jakým způsobem se nahrají do databáze počáteční data. Neodpovídejte však triviálním tvrzením, např. spustí se tento skript. Odpovězte, kde nebo jak jsou zdrojová data uložena, a co dělá skript, který je importuje do databáze.

### Odpověď:

Počáteční data se nahrávají do databáze pomocí dvou skriptů:

### 1. **Zdrojová data - CSV soubor**

Zdrojová data jsou uložena v souboru [dataset_ptaci_final.csv](../dataset_ptaci_final.csv) v kořenovém adresáři projektu.

Soubor obsahuje data o ptácích ve formátu CSV s následujícími sloupci:
- `nazev` - český název ptáka
- `vedecky_nazev` - vědecký název (latinský)
- `rad` - řád (taxonomická klasifikace)
- `celed` - čeleď
- `delka_cm` - délka těla v cm
- `rozpeti_cm` - rozpětí křídel v cm
- `hmotnost_g` - hmotnost v gramech
- `status_ohrozeni` - stav ohrožení (IUCN kategorie)
- `typ_potravy` - typ potravy (hmyzožravec, masožravec, atd.)
- `migrace` - zda je druh stěhavý (0 nebo 1)
- `vyskyt_kontinent` - kontinentní výskyt
- `snuska_ks` - počet mláďat ve snůšce

### 2. **Import skript - populate_csv.py**

Skript [populate_csv.py](../populate_csv.py) provádí následující operace:

```python
def populate_from_csv():
    with app.app_context():
        db.drop_all()                          # 1. Smaže všechny existující tabulky
        db.create_all()                        # 2. Vytvoří nové tabulky
        
        df = pd.read_csv('dataset_ptaci_final.csv')  # 3. Načte CSV soubor do DataFrame
        
        for _, row in df.iterrows():           # 4. Iteruje přes každý řádek
            bird = Bird(
                nazev=row['nazev'],
                vedecky_nazev=row['vedecky_nazev'],
                # ... další sloupce ...
            )
            db.session.add(bird)               # 5. Přidá objekt do session
        db.session.commit()                    # 6. Potvrdí všechny změny najednou
```

**Detailní vysvětlení procesu:**

1. **Čtení CSV** - Knihovna `pandas` otevře CSV soubor a načte jej do DataFrame (tabulka v paměti)
2. **Transformace dat** - Pro každý řádek se kontrolují null hodnoty (`pd.notna()`) a konvertují se na správné datové typy
3. **Vytvoření objektů** - Na základě dat z CSV se vytváří objekty třídy `Bird`
4. **Batch insert** - Všechny objekty se přidají do databáze session pomoví `db.session.add(bird)`
5. **Commit** - `db.session.commit()` spustí jeden hromadný SQL INSERT dotaz pro všechny záznamy najednou (efektivnější než jednotlivé inserty)

Tímto procesem se importují všechna data ze CSV souboru do SQLite databáze `birds.db`.

## Otázka 4: Přístup uživatelů do aplikace

Jak jste vyřešili přístup uživatelů do aplikace?

### Odpověď:

**Aplikace v současné době nemá implementován žádný systém autentifikace či autorizace.**

Všechny funkce jsou veřejně dostupné bez přihlášení:
- Každý může vidět seznam ptáků na domovské stránce
- Každý může přidávat nové záznamy o ptácích
- Každý může prohlížet statistiky

To je **bezpečnostní slabina**, která by měla být vyřešena implementací:

1. **Registrace a přihlášení** - Systém uživatelských účtů
2. **Autentifikace** - Ověření identity uživatele
3. **Autorizace** - Kontrola oprávnění pro jednotlivé operace (např. pouze administrátor může přidávat)

Pokud by se měl autentifikační systém implementovat, vypadal by takto:

```python
from flask_login import LoginManager, UserMixin

login_manager = LoginManager()
login_manager.init_app(app)

class User(UserMixin, db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)
    password = db.Column(db.String(255), nullable=False)
```

## Otázka 5: Ukládání hesel

Jakým způsobem ukládáte hesla?

### Odpověď:

**Aplikace v současné době **neukládá žádná hesla**, protože nemá implementován autentifikační systém.**

V případě budoucí implementace by se hesla měla ukládat následujícím způsobem:

### Správný postup (co dělat):

1. **Hashování hesla** - Heslo se nikdy neukládá v plaintext podobě
2. **Sůl (Salt)** - Přidá se náhodná hodnota k heslům pro ochranu před rainbow tabulkami
3. **Silný algoritmus** - Použít algoritmy jako bcrypt, argon2 nebo PBKDF2

### Příklad s `werkzeug` (součást Flasku):

```python
from werkzeug.security import generate_password_hash, check_password_hash

class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)
    password_hash = db.Column(db.String(255), nullable=False)
    
    def set_password(self, password):
        self.password_hash = generate_password_hash(password)
    
    def check_password(self, password):
        return check_password_hash(self.password_hash, password)
```

**Ukládané data v databázi:**
- Místo: `password_hash` sloupec v tabulce `user`
- Formát: `pbkdf2:sha256$260000$...` (zahashované heslo s algoritmem a iteracemi)
- Heslo je je **nezpětně transformováno** - nelze jej obnovit z hashe

### Bezpečnostní principy:

✅ **Korektní přístup:**
- Ukládat pouze hashe hesel
- Použít sůl (salt)
- Použít moderní algoritmus (bcrypt, argon2)
- Nikdy neodesílat hesla emailem či logovat je

❌ **Chybný přístup:**
- Ukládat hesla v plaintext
- Šifrovat hesla (lze dešifrovat)
- Ignorovat sůl

## Otázka 6: Řešení přihlášení pro operace

Jak je řešeno, že danou operaci, např. úprava záznamu, může provést pouze přihlášený uživatel? Vložte ukázku kódu, který to řeší.

### Odpověď:

**Aplikace v současné době nemá implementován žádný systém kontroly přihlášení.**

Všechny operace (přidávání ptáků) jsou dostupné komukoliv bez přihlášení.

### Jak by se mělo řešit - s Flask-Login:

```python
from flask_login import LoginManager, login_required, current_user

login_manager = LoginManager()
login_manager.init_app(app)
login_manager.login_view = 'login'  # Přesměrování na login stranu

@app.route('/add', methods=['GET', 'POST'])
@login_required  # Dekorátor - vyžaduje přihlášeného uživatele
def add_bird():
    if request.method == 'POST':
        # Pouze přihlášený uživatel se sem dostane
        nazev = request.form['nazev']
        vedecky_nazev = request.form['vedecky_nazev']
        # ... zbytek kódu ...
        new_bird = Bird(...)
        db.session.add(new_bird)
        db.session.commit()
        return redirect(url_for('index'))
    return render_template('add_bird.html')

@app.route('/edit/<int:bird_id>', methods=['GET', 'POST'])
@login_required  # Kontrola přihlášení
def edit_bird(bird_id):
    bird = Bird.query.get(bird_id)
    if not bird:
        return redirect(url_for('index'))
    
    # Dodatečná kontrola - pouze vlastník nebo admin může editovat
    if current_user.id != bird.user_id and not current_user.is_admin:
        return redirect(url_for('index')), 403
    
    if request.method == 'POST':
        bird.nazev = request.form['nazev']
        bird.vedecky_nazev = request.form['vedecky_nazev']
        # ... aktualizace dalších polí ...
        db.session.commit()
        return redirect(url_for('index'))
    
    return render_template('edit_bird.html', bird=bird)
```

### Vysvětlení:

1. **`@login_required`** - Dekorátor, který kontroluje, jestli je uživatel přihlášený
   - Pokud není, přesměruje na přihlašovací stránku (`login_view = 'login'`)
   - Pokud ano, pokračuje v provádění funkce

2. **`current_user`** - Objekt reprezentující aktuálně přihlášeného uživatele
   - Umožňuje kontrolu: `if current_user.is_authenticated`
   - Umožňuje zjistit ID uživatele: `current_user.id`

3. **Dodatečné kontroly** - Lze přidat logiku pro Role-based Access Control (RBAC):
   - Kontrola vlastnictví: `bird.user_id != current_user.id`
   - Kontrola práv: `current_user.is_admin`
   - Vrácení 403 Forbidden, pokud uživatel nemá práva

### Postup při přístupu bez přihlášení:

1. Uživatel klikne na "Add Bird"
2. Systém ověří `@login_required`
3. Pokud není přihlášený → **Přesměrování na /login**
4. Pokud je přihlášený → Povolení přístupu do funkce

Bez takového řešení by každý měl kompletní přístup k upravování dat, což představuje **bezpečnostní riziko**.
